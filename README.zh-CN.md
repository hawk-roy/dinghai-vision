# 定海灵眸 Dinghai Vision

[English](README.md) | [中文](README.zh-CN.md)

Dinghai Vision 是一个实验性的 AI 鱼缸视觉监控项目。

本项目的目标是构建一个第一版 MVP：使用相机、树莓派、计算机视觉模型、鱼体轨迹跟踪、行为特征计算和异常活动提醒，探索家庭鱼缸的纯视觉监控方案。

当前项目处于早期原型阶段。

## 项目背景

很多养鱼用户希望在外出时远程查看鱼是否正常活动，以及鱼缸中是否出现明显异常行为。

本项目探索一种纯视觉方案：

- 使用相机采集鱼缸视频。
- 在树莓派上运行鱼体检测模型。
- 持续跟踪鱼的运动轨迹。
- 计算鱼的行为特征。
- 使用简单规则判断异常活动。
- 生成本地状态数据和异常事件数据。
- 后续上传到云服务器，并在手机端展示。

第一版不包含水温、pH、TDS、水位、漏水检测或其他物理传感器。

## 项目代号

Dinghai Vision 的命名灵感来自中国古典名著《西游记》。

“定海”来自东海龙宫和如意金箍棒，也就是“定海神针”的意象，代表守护和稳定水域。“Vision” 代表用于监控鱼缸的 AI 视觉系统。

## MVP 目标

第一版 MVP 关注一个最小技术闭环：

```text
相机
  ↓
树莓派
  ↓
鱼体检测模型
  ↓
检测框 Bounding Boxes
  ↓
鱼体中心点
  ↓
轨迹跟踪
  ↓
行为特征计算
  ↓
异常事件规则
  ↓
本地 JSON / CSV 输出
  ↓
云端上传 / 手机端展示
```

第一版目标场景是：小型测试盒或小鱼缸、一条鱼、固定相机、稳定光照、干净背景。

## 第一版范围

第一版计划支持：

- 相机视频采集
- 本地图片和视频保存
- 使用 YOLO / Fishial / 自训练模型进行鱼体检测
- 输出检测框
- 计算鱼体中心点
- 记录单条鱼轨迹
- 计算基础行为特征
- 生成异常事件
- 本地输出 `status.json`、`events.json` 和 `tracks.csv`
- 后续支持云端上传和手机端展示

## 第一版不做什么

第一版暂不支持：

- 鱼病诊断
- 缺氧确诊
- 真实水质检测
- 藻类暴发预测
- 多鱼长期身份识别
- 复杂多目标跟踪
- 24 小时云端视频流传输
- 自动控制水泵、灯光、喂食器或加热棒
- 商业化硬件外壳设计

## 核心概念

鱼体检测模型不会直接判断鱼是否生病或健康。

检测模型只回答一个更简单的问题：

```text
这一帧里，鱼在哪里？
```

项目会基于多帧画面，进一步计算鱼的运动和行为。

整体逻辑如下：

```text
检测结果
  ↓
鱼体检测框
  ↓
鱼体中心点
  ↓
一段时间内的运动轨迹
  ↓
行为特征
  ↓
基于规则的异常事件
```

## 核心数据

### 检测输出

鱼体检测模型预期返回类似数据：

```json
[
  {
    "class": "fish",
    "confidence": 0.91,
    "bbox": [120, 180, 260, 240]
  }
]
```

检测框格式为：

```text
[x1, y1, x2, y2]
```

鱼体中心点计算方式：

```text
center_x = (x1 + x2) / 2
center_y = (y1 + y2) / 2
```

### 状态输出

`status.json` 示例：

```json
{
  "device_id": "tank_001",
  "timestamp": "2026-07-24T15:20:30+08:00",
  "fish_count": 1,
  "activity_score": 0.76,
  "avg_speed": 18.4,
  "top_ratio": 0.12,
  "middle_ratio": 0.71,
  "bottom_ratio": 0.17,
  "status": "normal"
}
```

### 异常事件输出

`events.json` 示例：

```json
[
  {
    "device_id": "tank_001",
    "timestamp": "2026-07-24T15:22:10+08:00",
    "event_type": "low_activity",
    "level": "warning",
    "message": "检测到鱼活动量偏低，建议查看鱼缸。",
    "features": {
      "duration_sec": 600,
      "avg_speed": 2.1,
      "bottom_ratio": 0.82,
      "total_distance": 130
    }
  }
]
```

### 轨迹输出

`tracks.csv` 示例：

```csv
timestamp,track_id,center_x,center_y,speed,region
15:20:01,1,320,180,12.5,middle
15:20:02,1,335,185,15.8,middle
15:20:03,1,340,260,21.3,bottom
```

## 行为特征

第一版可能计算以下行为特征：

- `fish_count`：鱼数量
- `avg_speed`：平均速度
- `max_speed`：最大速度
- `total_distance`：总移动距离
- `activity_score`：活动量分数
- `top_ratio`：顶部区域停留比例
- `middle_ratio`：中部区域停留比例
- `bottom_ratio`：底部区域停留比例
- `stationary_time_sec`：静止时长
- `turning_score`：转向分数
- `circling_score`：疑似打转分数

这些特征都基于鱼体中心点在一段时间内的轨迹计算得出。

## 异常事件规则

第一版可能包含以下简单规则事件：

- `low_activity`：低活动
- `bottom_stay`：长时间底部停留
- `surface_stay`：长时间水面停留
- `possible_circling`：疑似打转

这些事件不是医学诊断，只是视觉行为提醒，目的是让用户更早查看鱼缸。

规则示例：

```text
如果鱼长时间停留在底部区域，
并且平均速度低于正常阈值，
则生成 bottom_stay 提醒。
```

另一个示例：

```text
如果鱼的总移动距离较长，
但始终停留在局部区域附近，
并且方向变化频繁，
则生成 possible_circling 提醒。
```

## 开发路线图

### 里程碑 1：相机采集

目标：

- 将相机连接到树莓派或开发电脑。
- 采集原始视频。
- 本地保存图片和短视频片段。

预期输出：

```text
raw_video.mp4
sample_frame.jpg
```

### 里程碑 2：鱼体检测

目标：

- 在鱼缸视频上运行检测模型。
- 绘制鱼体检测框。
- 保存带检测框的视频。

预期输出：

```text
annotated_video.mp4
```

### 里程碑 3：轨迹跟踪

目标：

- 计算鱼体中心点。
- 记录中心点随时间变化。
- 保存轨迹数据到 CSV。

预期输出：

```text
tracks.csv
```

### 里程碑 4：行为分析

目标：

- 计算速度、距离、活动量分数和区域停留比例。
- 生成本地状态数据。

预期输出：

```text
status.json
```

### 里程碑 5：异常事件检测

目标：

- 增加简单异常行为规则。
- 生成本地异常事件数据。
- 保存相关截图或短视频。

预期输出：

```text
events.json
event_snapshot.jpg
event_clip.mp4
```

### 里程碑 6：云端上传

目标：

- 将状态和事件数据上传到云服务器。
- 提供查询最新状态和历史事件的基础 API。

可能的 API：

```text
POST /api/device/heartbeat
POST /api/device/status
POST /api/device/event
POST /api/device/snapshot
GET  /api/device/latest
GET  /api/device/events
```

### 里程碑 7：手机端展示

目标：

- 在网页或小程序上展示最新状态、快照和异常事件。
- 显示鱼的活动状态和异常记录。

## 当前开发原则

本项目采用本地优先的 MVP 策略：

```text
先本地跑通。
验证鱼体检测。
验证轨迹记录。
验证行为特征。
验证异常事件。
再接云端。
最后做手机端界面。
```

在本地视觉闭环稳定之前，不应优先开发完整手机应用或实时云端视频流。

## 推荐开发顺序

推荐开发顺序如下：

1. 相机采集
2. 本地视频保存
3. 鱼体检测
4. 检测框可视化
5. 中心点计算
6. 轨迹记录
7. 行为特征计算
8. 异常事件规则
9. 本地 JSON / CSV 输出
10. 云端上传
11. Web 或小程序展示
12. 后期如有需要，再做实时视频

## 开发说明

### 优先本地原型

第一版原型应先在本地运行，不依赖云端。

一个成功的本地原型应能完成：

- 从相机采集视频。
- 在视频中检测鱼。
- 绘制检测框。
- 记录鱼体中心点。
- 生成轨迹数据。
- 计算基础行为特征。
- 生成本地状态和异常事件文件。

### 云端后置

只有在本地视觉流程稳定后，才应增加云端上传。

云服务器初期只需要处理：

- 设备心跳
- 状态上传
- 异常事件上传
- 快照上传
- 最新状态查询
- 历史事件查询

### 手机端最后做

手机端界面应在云端 API 有稳定真实数据之后再开发。

第一版手机界面可以非常简单：

- 设备在线/离线状态
- 最近快照
- 当前检测鱼数量
- 活动量分数
- 最近异常事件
- 异常事件历史列表
